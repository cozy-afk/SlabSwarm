## Benchmark golden cases (16)

The benchmark is a deterministic golden suite, not a performance measurement;
"duration" above is wall-clock time of the whole file and will vary by machine.
The authoritative signal is pass/fail of each case. Cases, grouped by dimension:

1. **Golden identity variants (2)** — equivalent component decompositions yield
   one landed-cost identity; buyer and seller policies stay distinct.
2. **Basis preservation (3)** — every known basis preserved verbatim; absent
   basis is UNKNOWN and ineligible; an ASKING amount is never promoted to SOLD.
3. **Lot exclusion (2)** — unknown-composition lots excluded; equal-split lots
   divided deterministically (300 / 3 = 100) and eligible.
4. **Provenance completeness (3)** — complete FX provenance converts (120 × 1.1
   = 132 BASE); incomplete FX rejected to null, never zero; missing components
   stay null with reduced confidence; media checksum is content-addressed.
5. **Insufficient-evidence deflection (3)** — no evidence deflects with UNKNOWN
   confidence and zero numeric prices; invented price deflected; uncited answer
   deflected and cited answer grounded but capped at MEDIUM.
6. **Deterministic/swarm parity (2)** — route fallback agrees with pure guardrail
   on deflection/confidence/citations/prices; ingested source provenance
   survives persistence.

Plus one media-checksum determinism case and the FX/deflection cases above
bring the file total to 16.

## Concerns for future runs

- `bun` is not on PATH in this environment; CI that literally runs
  `bun run lint && bun test` must install bun or switch to the equivalent npm
  scripts. The npm scripts are toolchain-agnostic (`tsx`/`tsc` from
  `node_modules/.bin`) and were verified green.
- Parity is exercised only on the no-provider deterministic fallback path; a
  configured swarm/LLM provider path is intentionally not simulated.
